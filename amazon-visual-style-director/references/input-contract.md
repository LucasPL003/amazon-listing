# Image creative brief input contract

Every visual-direction request must be an ordered list of dictionaries. Each entry must contain these non-empty fields, and every `image_id` must be unique across the list:

| Field | Required content |
| --- | --- |
| `image_id` | Unique identifier for the planned image. |
| `image_type` | Exactly `main` or `secondary`. |
| `sales_task` | The supported selling task for this image. |
| `product_truth_lock` | Product facts that the visual must preserve. |
| `target_user_and_scene` | The intended user and supported use setting. |
| `exact_copy` | Approved, final copy supplied by the Listing Agent. It is not generated by Image Gen. |
| `prompt_skeleton` | A grounded composition/scene direction for generation. |
| `prohibited_content` | Claims, brands, and other content the visual must exclude. |
| `font_rights` | Font licensing metadata with an approved `status` and font `path`. |

`font_rights.status` must be `user-provided` or `open-license`, and its `path` must identify the approved font file. `exact_copy.language` is required. For a secondary image, `exact_copy.headline` is also required; `subtitle` is optional.

## Main-image rule

Main images are text-free. A brief with `image_type: "main"` must supply no non-empty `exact_copy` value other than `language`: this includes `headline`, `subtitle`, `number_unit`, and `emphasis`. Image generation never creates final wording: approved copy is composited later using the supplied font-rights metadata.

## Representative secondary-image selection

The representative sample must be a secondary image. If one or more secondary briefs have `sample_candidate: true` (normalize Chinese `是` to true and `否` to false first), the first marked brief is selected. If no secondary brief is marked, the first secondary brief is selected. If the input contains no secondary brief, selection raises an error.

## Required composition manifest

```json
{
  "canvas": {"width": 1500, "height": 1500},
  "style_id": "product-style-v1",
  "font_rights": {"status": "open-license", "path": "C:/fonts/approved.ttf"},
  "layers": [
    {"kind": "color-block", "box": [780, 80, 640, 300], "fill": "#F3E7DD"},
    {"kind": "text", "text": "正確な見出し", "box": [820, 120, 560, 220], "size": 76, "fill": "#40352F"}
  ]
}
```

Every layer has an in-canvas `[x, y, width, height]` box. Supported deterministic layer kinds are `text`, `icon`, `shape`, `line`, `color-block`, and `shadow`; layers render in listed order. Text supports explicit line breaks and must fit its declared box. The output validator parses `composition.json`, checks its required fields, and compares `canvas`, `style_id`, `font_rights`, and `layers` with the manifest passed for validation.
