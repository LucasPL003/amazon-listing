# 工作流

## 1. 输入门

开始推荐前必须同时取得：

- `图片解析摘要`
- `附图策划`
- 原始产品图片
- 可明确识别的目标站点和图片文案语言

缺少任一项时立即停止，列出缺失项；不得推测产品结构、补写事实、创建完整提示词或调用 Image Gen。若文字分析与产品原图明显冲突，以原图作为视觉身份依据，并要求用户确认冲突事实。

## 2. 验证 Style Pack

运行：

```powershell
python scripts/validate_style_packs.py assets/style-packs
```

只使用验证报告中的 `packs`。向用户简要报告被排除套系的错误。当 `available_count` 为 0 时停止推荐和生成，并指向 `assets/style-packs/README.md`；空库不是创建虚构候选项的理由。

## 3. 推荐与选择

按品类、目标人群、购买情绪、使用场景、图片角色覆盖和产品色彩兼容性评估有效套系。显示得分最高的至多三个候选；不足三个时只显示真实数量。每个候选只展示视觉特点、适合原因和可能风险，不展示完整提示词。

等待用户明确选择一个 Style Pack ID。未选择前不得创建逐图设计或生成图片。整套图片始终使用同一 Style Pack。

## 4. 逐图设计审核

将每条 `附图策划` 映射为一张图片，每张图片只有一个核心销售任务。角色参考图优先；对应角色缺失时回退到 `generic`。按 `design-output-template.md` 展示逐图设计，并等待修改意见。

副图采用场景优先结构。结构、尺寸、步骤、分层材料和合规对比等仅承担信息解释的图片可以使用非场景背景，并且不计入场景比例；其余副图中至少 60% 必须是有真人或真实使用动作的使用场景图，数量向上取整。每张场景图的背景适配必须基于已确认的产品用途、目标人群和该图唯一销售任务：背景、人物、动作和道具只服务于这一个任务，不得虚构或暗示未经确认的功能、参数、效果或安全主张。

完整提示词、负面约束、事实映射和模型设置保持内部使用，除非用户明确要求查看。

## 5. 生成确认门

只有用户明确回复“确认生成”或含义等同的确认后，才能调用 Image Gen。确认前不得生成测试图、预览图或任何替代结果。

主图必须无文字。每张副图把画面和已批准的准确文案放在同一次 Image Gen 请求中。调用时同时提供原始产品图片、所选角色参考图和 `prompt-contract.md` 定义的内部记录。

## 6. 验收、返工与交付

按 `quality-checklist.md` 单独检查每张图。某张失败时只调整该图的内部提示词并重新生成，不改动已通过图片；自动返工最多 2 次。达到上限仍失败时保留当前最佳结果，列出未通过项并等待用户决定，不得宣称整套全部合格。

交付时逐图标明状态、使用的 Style Pack ID、参考角色、重试次数和未解决问题。
