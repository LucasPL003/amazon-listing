# Amazon Premium A+ Module Patterns

## Seven-module page rhythm

Use exactly seven modules. Before planning them, list all distinct A/B-evidenced selling points and identify 1–2 core selling points.

| Module position | Required role | Useful evidence |
| --- | --- | --- |
| 01 | Overview of all verified selling points | Product identity plus concise visual evidence for the complete selling-point inventory |
| 02 | First selected core selling point | Product-in-use scene, visible result, or direct proof |
| 03 | Second selected core selling point when one exists; otherwise first non-core QA | Product-in-use scene, visible result, or direct proof |
| Remaining positions | One non-core QA scene answer per module | Fact-supported usage scene plus a direct target-language answer |

Ordinary selling points do not receive standalone modules after module `01`. Remove any QA whose intent is already answered by a core module, even if it uses different words. Deduplicate equivalent remaining questions. If there are too many, prioritize purchase-decision value, evidence strength, and scene proof. If there are too few, add fact-derived questions about suitability, use, compatibility, package contents, care, or limitations; never relabel an ordinary selling point as QA.

## Mobile and desktop composition

Create mobile images at `1200×900` first. Prefer a clear focal product, one primary message, and readable copy with generous edge margins. Keep adjacent modules visually connected through palette, lighting, materials, or recurring motifs, but vary zoom, subject position, and information density.

Create each desktop image at `1464×600` from a separate specification. Use the horizontal canvas intentionally: reserve whitespace for copy, rebalance product scale, and adapt reading direction. Never resize, stretch, or crop mobile pixels to make desktop artwork.

## Copy and claims

- Keep visible copy short, specific, and in the target marketplace language.
- Use only supplied or visibly supported claims. Flag assumptions for review.
- Avoid prices, promotions, discounts, reviews, guarantees, competitor claims, contact information, QR codes, URLs, unsupported certifications, and absolute-superiority claims.
- Do not repeat the same headline grammar. Core selling points may reappear as short context in module `01`, but they must not reappear as QA modules.

## Preview and delivery checks

1. After modules `01` and `02`, inspect both assets and a `1200×1800` mobile preview before the second approval gate.
2. After all mobile images, create and inspect `移动端整页预览_1200x6300.jpg`; obtain mobile-package confirmation.
3. After all desktop images, create and inspect `PC端整页预览_1464x4200.jpg`.
4. Verify 14 RGB PNG/JPG images, exact dimensions, sequential `1`–`7` mobile/desktop pairing, legible text, and a complete `A+内容.md`, `上传清单.md`, and `验证报告.md` package.
